MediBot · MediAssist Health Network

Advanced RAG with role-based access control

Staff ask questions in natural language and get cited answers drawn from hospital documents — but only from the documents their role permits. Retrieval combines dense vector search with BM25 keyword search, a cross-encoder narrows the candidates, and a relational branch handles analytical questions that no PDF can answer.

The design thesis: access control is a metadata pre-filter on the vector search, not an instruction in a system prompt. The LLM never receives a restricted chunk, so it cannot leak one — no matter how the question is phrased.

Diagram 1 · Who can see what

Five roles, five document collections, one analytical branch

This matrix lives in exactly one Python dict. The access_roles label written onto every chunk at ingestion time is derived from it, and the query filter applied at retrieval time reads from it — so the two can never drift apart. That drift is the most likely source of a silent access leak.

One spec ambiguity, resolved. The assignment's role table gives doctor only clinical documents plus general, but its data-sources table lists nursing as accessible by nurse, doctor, and admin. The more specific statement wins, so doctor gets nursing — a physician reading ICU nursing procedures is clinically sensible. Say this in the README so a reviewer reads it as a decision rather than a bug.

Diagram 3 · Where the filter sits

The difference between an access control and a suggestion

Both approaches produce a correct-looking answer. Only one of them is access control. This distinction is 25% of the grade, and it is the single thing most implementations get wrong.

# The whole mechanism. A top-level query_filter propagates recursively into
# every prefetch branch and is applied BEFORE each branch's limit.

client.query_points(
    collection_name="medibot_documents",
    prefetch=[
        models.Prefetch(query=q_dense,  using="dense", limit=20),
        models.Prefetch(query=q_sparse, using="bm25",  limit=20),
    ],
    query=models.FusionQuery(fusion=models.Fusion.RRF),
    query_filter=rbac_filter(role),   # ← one place. both branches. pre-filter.
    limit=20,
)

Two details that decide whether this is correct. MatchValue(value="nurse") against a list-valued access_roles field means contains — Qdrant's docs: “if several values are stored, at least one of them should match.” And MatchAny is more permissive, not stricter: it ORs across the given values. Swapping to it later, thinking it tightens the check, would be a privilege-escalation bug. Leave a code comment saying so.

Diagram 4 · The narrowing

From the whole corpus to three passages

Two independent narrowings happen, and they do different jobs. The first is a policy decision — it cannot be relaxed for better answers. The second is a quality decision — tuning it changes answer quality but never who can see what.

Why the cross-encoder is worth its latency. Hybrid retrieval scores the query and each chunk independently — embeddings are computed without knowledge of each other. A cross-encoder reads the pair together in one forward pass, which is far more accurate and far too slow to run over a whole corpus. Running it on 20 candidates buys most of the accuracy for none of the cost.

Log the scores during development. You will regularly see the 4th or 5th hybrid result outscore the 1st — capture one of those logs as a README screenshot. It is more convincing than any claim you could write.

Diagram 5 · Ingestion

How a PDF becomes a retrievable, access-labelled chunk

Run once, offline, before anything else works. The critical property is that a chunk's embedded text is not the raw paragraph — it carries the heading path above it, so "25mg twice daily" becomes something both the embedder and the LLM can actually use.

# What contextualize() actually produces — verified, not assumed

chunk.text     → "Employees accrue paid leave monthly according to tenure."
meta.headings  → ["Employee Handbook", "Leave Policy"]

contextualize(chunk) →
    Employee Handbook
    Leave Policy
    Employees accrue paid leave monthly according to tenure.

# Embed the contextualized form. Store and cite chunk.text.

payload = {
    "source_document": "hr_handbook.pdf",
    "collection":      "general",
    "access_roles":    ["admin", "billing_executive", "doctor", "nurse", "technician"],
    "section_title":   "Employee Handbook > Leave Policy",
    "chunk_type":      "text",   # text | table | heading | code
    "text":            chunk.text,  # raw text, for citation display
}

access_roles is derived, never typed. It comes from the same dict the query filter reads. Hand-writing the list per collection is how a billing document quietly ends up readable by everyone — and nothing in the system would tell you.

⚠ Three library behaviours that fail silently — no exception, no warning

  1. HybridChunker(max_tokens=512) is ignored when a real tokenizer object is passed. Set max_tokens on the tokenizer, and assert chunker.max_tokens at startup.
  2. repeat_table_headers (plural) is swallowed by pydantic. The real field is repeat_table_header, singular.
  3. The cross-encoder repo is now ms-marco-MiniLM-L6-v2. The L-6-v2 spelling copied across most tutorials is the legacy name.

Defence in depth

Five layers, so one mistake is not a breach

Layer 2 is the actual enforcement. The others exist so that a regression becomes loud rather than silent.

Layer 1 · Token
Role is decoded server-side from the bearer token. A role field in the request body is discarded.
Layer 2 · Query filter
The real enforcement — a Qdrant pre-filter on access_roles, propagated into both hybrid branches.
Layer 3 · Assertion
Every returned chunk is re-checked against the matrix. A violation logs CRITICAL and raises rather than answering.
Layer 4 · Prompt
“Answer only from the context. Never comment on what other roles can access.” Stops confirming restricted collections exist.
Layer 5 · Refusal
An empty result set returns a role-scoped explanation naming the permitted collections — the LLM is never called.

Test the retrieval, not the answer. Asserting that the response text contains no billing codes proves the model behaved this once. Asserting that no chunk with collection == "billing" was retrieved proves it cannot misbehave. The adversarial suite asserts on retrieval.
